## Controles reforzados

- **Recibo de escaneo ligado a candidata.** `scan_release_image.py` calcula SHA-256 del Docker archive completo y del config de imagen; exige un único manifest, rechaza paths duplicados, metadata no regular/excesiva y config distinto de su digest. No extrae tar al filesystem. Registra image_id, archive_sha256, fecha UTC y estado de DB en el recibo. Hashes vinculan los bytes examinados; no son firma ni aprobación de un tercero.

Rechaza manifest/gates mal formados o evidencia en blanco. Conserva GO_FOR_REVIEW sin autorizar despliegue; todos los gates siguen siendo necesarios. La validación no depende de asserts: prueba con Python `-O` rechaza un hash alterado.
- **Entorno del scanner restringido.** Se transmiten solo PATH/locale y configuración de transporte/TLS necesaria. Se excluyen claves Supabase, GH_TOKEN y overrides GRYPE_/SYFT_ del proceso. HOME/cache propios y configs explícitas impiden que defaults del checkout y variables heredadas supriman matches. Se fijan ignore/exclude vacíos, only-fixed/only-notfixed desactivados, sin ignorar wont-fix, validación de hash/edad DB habilitada. La importación offline aún exige archivo oficial y checksum de confianza.
- **Menos privilegios.** API, MediaMTX, vision-worker y vision-fleet eliminan capacidades Linux y usan no-new-privileges. API/gateway limitan PIDs a128; workers mantienen sus límites previos. /tmp de worker/fleet agrega noexec,nosuid,nodev. La API conserva su filesystem escribible existente por compatibilidad del fallback; no se anuncia aislamiento read-only de API Compose.
- **MediaMTX sin root.** Compose usa MEDIAMTX_UID/MEDIAMTX_GID (1000/1000 por defecto), que deben coincidir con el propietario de su config privado. Fixtures usan UID/GID del ejecutor y docker cp -a para conservar propiedad. No se hace chmod world-readable ni se devuelve DAC_OVERRIDE para leer un archivo600.
